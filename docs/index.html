FOUNDRY · SANDBOXED · PORTABLE · KEYBOARD-FIRST

The modern IDE workflow,
inside Emacs.

Foundry is a modular Emacs configuration with IDE-style tool windows, a first-class Azure DevOps forge in Magit, Kubernetes, Docker and Terraform porcelains, inline AI completion and a literate Org knowledge base — installed entirely under one directory and launched next to your daily-driver setup.

01Overview

Four ideas hold the design together.

Tool windows, not split chaos

Compilation output, terminals, diagnostics, container logs and cloud consoles dock into a single bottom drawer (popper + display-buffer-alist). The project tree sits left, the structure outline right. Esc always returns focus to your code.

Zero dotfile pollution

Everything — packages, caches, auto-saves, databases, even the installed CLIs and Azure login state — lives inside ~/.config/emacs-foundry/. Your ~/.emacs.d is never touched.

No browser required for DevOps

Pull requests, review threads, votes, completion, Boards work items and pipeline status are driven through the Azure DevOps REST API and surfaced as Magit sections and transient menus.

Portable tooling

One mise.toml declares 24 CLIs and language servers. M-x ide-mise-setup (or make tools) bootstraps a checksum-verified mise and installs them into the sandbox on any Linux or macOS machine.

02Quick start

Requires Emacs 29.1+ (developed on 31.1), git and curl. Packages install themselves on first launch.

# 1. launch beside your normal Emacs
cd ~/.config/emacs-foundry
./launch.sh

# 2. optional: add it to your application menu
make desktop

# 3. install the CLIs and language servers (≈2 GB)
make tools

# 4. see what is available
make doctor

04Keybindings

Every binding below is read from the live configuration and checked by a script (make docs-check). M- is Alt (Option on macOS). Press / to search.

Turn on, then press real key chords on this page. Prefixes like C-c show what can follow, like which-key. Esc twice to leave.
No standard editing keys are replaced Foundry only binds C-c + letter (reserved for users), M-s (the search prefix), C-= and function keys. Go to definition and usages use the standard M-. and M-?, and C-s stays Isearch. M-RET for code actions is bound in programming modes only, so Org and Markdown keep theirs.

08Make it yours

Add your own packages, tools and settings without touching the IDE's core. Everything of yours lives in user/, loads last, and is never overwritten.

Where things go

user/
├─ packages.el    ← written by C-c u a
├─ 10-rust.el     ← any *.el, loaded alphabetically
├─ settings.el
└─ mise.toml     ← extra CLI tools for M-x ide-mise-setup
examples/
└─ shipped samples you can copy into user/

Safe by design

  • Core files are never edited, and core updates never touch user/.
  • A broken file shows a warning and the rest still load. Start Foundry (safe mode) from your launcher, or run ./launch.sh --safe, to skip them all.
  • Packages install into the sandbox like the built-in ones; tools from user/mise.toml go into var/mise/.
  • make compile and make test ignore user/.

Three ways in

C-cuaide-user-add-package: a name (and optionally a GitHub repo) is appended to user/packages.el and installed in the background. A prefix argument loads it at startup.
C-cuiide-user-install-example: copy a shipped example into user/.
C-cunide-user-new-file, or just create any user/*.el yourself. C-c u e opens the folder and C-c u r reloads without a restart.

Conventions that keep it tidy

  • Keep data in the sandbox with ide-var-dir (var/) and ide-cache-dir (.cache/).
  • Put your keys on ide-keys-mode-map; C-c x is free for you.
  • Dock a tool's buffers in the bottom drawer with (ide-add-drawer-buffer "\\*name\\*").
  • Adjust a core package inside with-eval-after-load; run things that need everything loaded from elpaca-after-init-hook.
  • Prefix file names (10-, 20-) to control load order.

09Architecture

Modules load in numeric order from init.el; each is small and independently readable. Packages are managed by elpaca and installed asynchronously after the first frame appears.

Directory layout

How startup stays fast

  • First frame in roughly 85 ms (measured in a terminal session): early-init.el raises GC limits and suppresses UI chrome, init.el only queues packages.
  • Packages install and activate in the background; use-package defers everything not needed immediately.
  • The config's own files are byte-compiled but deliberately not native-compiled, because the background compiler cannot see our macros.
  • The mise tool PATH is cached in var/mise/path.eld — startup never spawns mise.
  • Batch runs (make test, make tools) wait for packages so results are deterministic.

10Tools via mise

Declared in mise.toml, installed by M-x ide-mise-setup into var/mise/. mise's data, state and cache are redirected into the sandbox; an existing mise on your PATH is used but never modified, and mise never reads configuration from parent directories such as ~/.tool-versions.

11Setup & credentials

Azure DevOps

The organization, project and repository are inferred from the git remote (https, ssh and visualstudio.com forms). Authentication, first match wins:

  1. AZURE_DEVOPS_EXT_PAT environment variable
  2. An auth-source entry for host dev.azure.com
  3. az login (Entra token, cached 50 minutes)

Azure CLI state lives in var/azure/, so log in once inside the IDE. Set ide-azure-config-dir to nil to share ~/.azure.

Confluence Cloud

Set confluence-site (the part before .atlassian.net) and provide credentials:

  • CONFLUENCE_EMAIL and CONFLUENCE_API_TOKEN, or
  • an auth-source entry for <site>.atlassian.net

Inline AI completion

Default backend is a local Ollama at localhost:11434 with qwen2.5-coder:7b. Switch with M-x ide-ai-switch-backend to gemini (GEMINI_API_KEY) or an OpenAI-compatible FIM endpoint. Files matching ide-ai-private-file-regexps (.env, *.tfvars, keys, kubeconfig, secrets) are never sent to hosted models; M-x ide-ai-mark-private protects any other buffer. Chat and gptel-agent also use ANTHROPIC_API_KEY if set. Pick the chat and agent model with C-c a M, or fix a default with ide-ai-default-model such as (claude . claude-sonnet-5-5); point gptel-agent-skill-dirs at extra skill folders (~/.claude/skills and installed Claude Code plugins are found automatically).

Keeping this page current

C-c h u (M-x ide-docs-update) compares this page with the running configuration. Keys, menus, tools, modules, make targets and counts are rewritten from facts, so they cannot drift. Only new or changed items go to your configured AI agent (gptel by default) for wording, as validated JSON — the agent never writes HTML.

The result is checked in a fresh Emacs and replaces the page only if it passes; the previous page is backed up. make docs-update does the factual part without an agent, and M-x ide-docs-update-with-agent starts a gptel-agent session with the task, which you review and send.
